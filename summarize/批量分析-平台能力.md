# 批量关键词分析：平台能力说明

> 面向"关键词 → 批量下载指定条数 → 转写 → 总结"这条需求，三个平台的实际情况不同。
> 下面是实测结论与用法，**不含想象**。

---

## 一句话结论

| 平台 | 关键词搜索 | 批量下载 | 转写+总结 | 结论 |
|---|---|---|---|---|
| **YouTube** | ✅ 内置 `ytsearch` | ✅ | ✅ | **全自动**（需登录态 cookie） |
| **B站** | ⚠️ 有 `bilisearch`，但需 cookie + 412 风控 | ✅ | ✅ | **全自动，但会偶发失败需重试** |
| **抖音** | ❌ 搜索接口要 `a_bogus` 签名，无解 | ⚠️ 单条分享页方案可用 | ✅ | **半自动：给链接列表** |
| **小红书** | ❌ 无公开接口 | ⚠️ yt-dlp 有提取器，未实测 | ✅ | **半自动，实验性** |

> 下载和转写是通用的；**"关键词搜索"是按平台定制的，且多数平台没有公共接口**。

## 用法

```powershell
$py = "$env:LOCALAPPDATA\Programs\whisper\venv\Scripts\python.exe"
cd "<仓库目录>\summarize"

# B站：关键词 → 前 3 条 → 转写 → 汇总
& $py batch_platform.py bilibili "Python 教程" --count 3 --max-duration 600 --model small

# 抖音 / 小红书：链接列表（每行一个）
& $py batch_platform.py links links.txt --platform douyin --model small
& $py batch_platform.py links notes.txt --platform xhs --model small
```

或者双击 **`批量分析.bat`**，按菜单选 1/2/3。

产物在 `out\batch_<日期>_<关键词>\`：

```
01_<标题>.md        单条：要点 + 关键词 + 全文（带时间戳）
01_<标题>.srt       字幕
汇总.md             所有条目的索引 + 关键词 —— 拿这个去让 AI 做横向对比
```

## B站：为什么必须带 cookie，为什么偶尔失败

- `bilisearch` 走的是 B站搜索接口，**未登录 + 无 `buvid3` 会直接 412**；
- 即使带 cookie，短时间内反复请求也会触发 412（Precondition Failed），属于平台风控；
- 脚本做了两件事：**优先读 Firefox 的实时 cookie**（`--cookies-from-browser firefox`），
  以及**412 时自动退避重试**（10s / 20s，最多 3 次）。

实测数据（tiny 模型，2026-11-16）：

| 项目 | 结果 |
|---|---|
| 搜索（第 3 次重试后成功） | ✅ 返回可用条目 |
| 单条音频下载 | ✅ 5 MB wav |
| 转写速度 | ✅ **8.7 – 9.5 倍实时**（tiny）；small 约 1.6–2.2 倍 |
| 全流程 | ✅ 2 条约 50 秒（tiny） |

**注意**：B站搜索返回的是 `aid`，多 P 视频默认只下第一 P（p1）。要下其他分 P 或整季，
直接给具体链接（`.../video/BVxxxx?p=2`）走 links 模式更稳。

## 抖音：为什么没有"关键词搜索"

抖音搜索页（`douyin.com/search/关键词`）返回的是 72 KB 的 JS 空壳，
真实结果来自需要 `a_bogus` 签名的接口 —— 那是段被混淆的 JS VM，社区通用做法是引入签名库。
本工具**不内置这种签名**，所以：

- 关键词 → 需要你自己（或别的工具）先得到链接列表；
- 拿到链接后放进 `links.txt`，一条一行，脚本会用已有方案下载并转写。

实测：单条分享链接（`v.douyin.com/xxx`）能下 720p 无水印 mp4，再抽音频转写没问题。
**但并发请求会立刻触发风控**，所以脚本是逐条串行。

## 小红书：视频笔记可用，图文笔记跳过（v3.1 已接 xhs.js）

v3.1 起 `batch_platform.py` 的 `download_audio()` 对 `platform == "xhs"` 不再走 yt-dlp（图文笔记会报 `No video formats found!`），改调 `xhs/xhs.js`：视频笔记取 `video.mp4` 转 16kHz wav 后转写；图文笔记没有音频，会明确提示跳过，不会误报失败。链接仍需带 `xsec_token` 或用 `xhslink.com` 短链，且 Firefox 里要有小红书登录态。**视频分支代码已做单元测试，宿主环境端到端仍待实测。**

## 想加更多平台怎么办

判断顺序（从易到难）：

1. `yt-dlp --list-extractors | findstr 关键词` —— 有没有该站提取器（决定能不能下）；
2. 有没有 `xxx:search` 提取器（决定能不能按关键词搜）；
3. 都没有 → 就只能"链接列表"模式，搜索交给搜索引擎/人工。

目前 yt-dlp 自带 search 提取器的站点很少：YouTube、B站、SoundCloud、Dailymotion、Niconico 等十余个。
